# 电子科技大学教务课表导入研究

核查日期：2026-10-08。本文研究电子科技大学本科 EAMS 网页，以及相关开源项目的公开源码。用户已在 Edge 完成学校认证，通过“课程管理 → 我的课表”进入真实课表；已读取课表的结构与显示形式。本文不记录姓名、学号、实际课程名称、教师或教室等个人数据。仍区分“真实网页核实”“源码推断”和“待 Android 验证”。没有尝试账号、密码或绕过认证。

## 结论与实施方向

导入具有可行性：网页把课程安排作为结构化 `TaskActivity` 数据发送给浏览器；已经渲染的课表单元格也包含课程、教师、地点和教学周文本。Android 可让用户在学校网页自行登录，打开目标学期课表后，在本机提取并预览这些信息，再由用户确认导入。

本次 Edge 验证已确认学校课表的实际数据结构。Edge 仅用于结构验证，它的登录会话不会自动进入 Android 应用；手机端仍需要用户在应用内置 WebView 重新登录。用户后续手机截图已显示登录后的首页，但菜单和样式缺失；**打开课表、提取、预览并保存的完整手机流程仍待验证。**

### 1.2.0 整页加载兼容修复

在 Android 11 模拟器复现真实登录首页缺少样式和外部脚本的问题，jQuery、bg 未定义。单独使用电脑版或改变视口没有恢复资源；使用正常 HTTPS 整页请求后，首页的 4 份样式和菜单脚本恢复。用户随后确认课表能读取。

应用为学校教务整页 GET 增加兼容加载，避免旧 WebView 的请求标识影响完整文档响应。仅对 `eams.uestc.edu.cn/eams/` 的主框架 GET 生效；登录 POST、AJAX 和子资源保留浏览器原有行为。登录会话仅发回当前学校 HTTPS 地址，重定向由 WebView 在学校域名范围内处理，不在网络层携带 Cookie 跟随跨域跳转，不记录会话值或加入课表备份。

### 1.1.1 手机显示兼容改动

针对用户反馈，教务 WebView 默认以桌面 Chrome 标识请求页面，保留设备实际内核版本，移除 Android、Mobile 和 WebView 标记。教务域名页面采用 1280 像素桌面视口并允许双指缩放；学校认证页面保留自身视口。用户可切换「电脑版」并刷新当前页面，登录会话不随模式切换清空。增加已核实的官方「我的课表」直达入口，便于首页菜单异常时进入课表。

模拟器上的真实 WebView 已验证桌面响应式布局生效、原生手机标识和布局可恢复；截图中样式及菜单失败的具体原因、该改动在用户手机上的实际效果尚待验证。未将用户手机截图或身份信息写入源码包。浏览器标识与布局 API 依据为 [Android WebSettings](https://developer.android.com/reference/android/webkit/WebSettings)。

建议优先支持已渲染的课表 HTML，同时支持树维/WakeUp 导出的 JSON 文件作为备用途径。两种方式都不需要应用收集账号密码。学期开始日期和学校作息应从实际网页获取或让用户确认，不能由当前日期、学期 ID 或第三方硬编码值猜测。

## 已实时读取的学校资源

- 用户指定的[课表入口](https://eams.uestc.edu.cn/eams/courseTableForStd!courseTable.action)：未登录的普通 HTTP 请求返回用于动态浏览器验证的页面壳，没有课表数据。仅靠 HTTP 状态成功不能认定课表已取回。此次验证从[教务首页](https://eams.uestc.edu.cn/eams/)进入，用户完成登录后，通过“课程管理 → 我的课表”成功显示课表。
- 学校公开的[TaskActivity.js](https://eams.uestc.edu.cn/eams/static/scripts/course/TaskActivity.js)：可在无需登录时读取。该文件定义 `CourseTable`、`TaskActivity`、周次格式化和表格渲染方法；本次真实网页也已确认 `CourseTable`、`unitCount`、`marshalTable` 和带 `title` 的课表单元格存在。

### 登录后真实网页结果

| 核实项 | 本次观察 |
| --- | --- |
| 整周网格 | `CourseTable(2026, 84)`，7 天共 84 格 |
| 每天节数 | `unitCount = 12` |
| 教学周显示参数 | `marshalTable(2, 1, 20)` |
| 有课程内容的单元格 | 18 个 `TD` 带 `title` |
| 实际科目 | 9 个；同一科目可能产生多条时间或周次安排 |
| 连续节次 | `rowspan` 出现 1、2、4 |
| 多安排 | 存在一个单元格内多门课程，以及同课程分段周次中途换教室 |
| 地点 | 存在没有教室字段的课程 |
| 离散周次 | 存在 `连1-4 6`、`连1-4 连6-14` 等表达式 |

这些观察验证了当前课表必须保留离散周次、同格多课和分段地点，不能将一科目简化成唯一连续周区间。这里的 9 个科目、18 个内容单元格也不能直接当作最终导入条目数：应用需按时间、地点和精确周次拆分安排。

公开静态源码的核心结构如下，参数名称与原文保持一致：

| 结构 | 含义 |
| --- | --- |
| `CourseTable(year, unitCounts)` | 年份和整周网格数；`unitCounts` 是整周数量，不能直接当每天节数 |
| `activities[index]` | 一个网格中的活动数组；同一节可有多个课程或不同周次安排 |
| `teacherId` / `teacherName` | 教师标识及显示名 |
| `courseId` / `courseName` | 课程标识及显示名 |
| `roomId` / `roomName` | 教室标识及显示名 |
| `vaildWeeks` | 周占用位串；`vaild` 的拼写错误属于原始字段名 |
| `marshalContents[index]` | 已按页面周次参数格式化的课程、教师、周次和地点文本 |

`TaskActivity` 的前七个位置参数为教师 ID、教师名、课程 ID、课程名、教室 ID、教室名、周占用位串。后续可有任务 ID、备注或其他版本新增字段。解析器应识别所需前七个参数，并允许后续字段存在。

### 周次不能无条件按“第几个 1”转换

学校公开 `TaskActivity.js` 的 `marshal(weekOccupy, from, startWeek, endWeek)` 根据 `from` 转换周号，显示教学周为 `位串下标 - from + 2`，并处理跨年安排。**不能把位串中的第一个 `1` 当成第 1 教学周。**

本次真实页面使用 `marshalTable(2, 1, 20)`，因此在这一课表中下标 1 对应第 1 教学周，下标 5 对应第 5 教学周；其他页面若 `from` 不同，位串与教学周的对应关系也不同。对 HTML 静态脚本解析，应读取实际 `marshalTable(...)` 调用；对已渲染内容，课程的周次文本已经完成这一步转换。公开源码还包含跨年左移逻辑，因此日期跨年时不能只套简单公式。

## 公开开源项目给出的兼容格式

### UESTC 已渲染课表 DOM

[Saafo/uestc-coursetable-parser](https://github.com/Saafo/uestc-coursetable-parser) 的 [course2ics.js](https://github.com/Saafo/uestc-coursetable-parser/blob/master/course2ics.js) 与 [course2Mi-AI.js](https://github.com/Saafo/uestc-coursetable-parser/blob/master/course2Mi-AI.js) 从 `TD{index}_0` 的 `title` 和 `rowspan` 读取课表。

源码所支持的显示形态为：`教师 课程名(课程标识);(教学周表达式,地点)`，一个 `title` 可能含多组课程及周次信息。连续周、单双周、分段周和单独一周需要分别解析。例如 `连1-18`、`单1-17`、`双2-16`、`1-3 7 10-12`。地点可能为空，也可能自身包含逗号，课程名称可能有括号和空格。

这些脚本固定每天 12 节、整周 84 格，与本次登录后的真实课表一致。实现仍应优先读取页面 `unitCount`、网格数量或节次标题，不能将其他树维 EAMS 学校常见的 13 节套用于此页面。源码采用 GPL-3.0；本项目可以据此研究协议，直接复制实现需要相应处理许可证。

### Classic EAMS HTML 中的脚本

其他树维 EAMS 项目的[公开原始数据示例](https://github.com/Hackathon2019EastChina/Super_iCal-SeeWhatYouLittleBaldHead#raw-data) 给出 `activity = new TaskActivity(...)` 后连续写入 `index = D * unitCount + P` 的形态。`D` 和 `P` 都从 0 开始，分别对应星期和节次，同一个活动可写到多个相邻格。

教师参数不一定是字符串字面量，也可能为 `actTeacherName.join(',')`，需要从对应的 `actTeachers` 数组读取。`teachers` 数组可能代表整个课程的全部教师，不能不加区分地作为这次课的实际教师。该示例是其他学校的原始公开数据，只能作为 Classic EAMS 协议的交叉依据，不能视为 UESTC 现行页面的实测结果。

### WakeUp 树维文件

[WakeUp 官方树维简易导入说明](https://www.wakeup.fun/doc/shuwei.html) 的导出脚本读取当前文档或同源 iframe 的 `table0`，补充页面 `unitCount` 后进行 JSON 序列化；下载扩展名虽然为 `.html`，文件内容实际是 JSON。

导入器应识别 `activities` 二维网格数组。每天节数优先取 `unitCount`；必要时可在确认整周 7 天的前提下由 `unitCounts / 7` 推得。课程字段使用 `courseName`、`teacherName`、`roomName`、`courseId`、`vaildWeeks`；可以兼容有些导出器修正后的 `validWeeks`。同一活动出现在连续多格时，应按同一星期、课程、教师、地点、周次合并成一个连续节次安排，不能跨越空格或不同属性误合并。

这类 JSON 还可能含已格式化的 `marshalContents`。若原始周位串缺少周起点参数，优先使用已显示的教学周文本，或明确提示无法准确确定；不要悄悄把课程前移。官方导出脚本没有保证文件包含开学日期。

### 新版 UESTC Android 项目

[MilLoong/UESTC-EAMS-Helper-App](https://github.com/MilLoong/UESTC-EAMS-Helper-App) 当前源码同时提供网页登录和 WakeUp 文件导入。研究使用版本为 `e8d73160f2b7e4e74df389053e0dcecbca144531`，主路径如下：

- [WakeUpShuweiHtmlParser.kt](https://github.com/MilLoong/UESTC-EAMS-Helper-App/blob/e8d73160f2b7e4e74df389053e0dcecbca144531/app/src/main/java/edu/uestc/eams/helper/data/parser/WakeUpShuweiHtmlParser.kt)：支持网格 JSON、`startUnit`/`endUnit` 和一些可选起始日期字段。
- [EamsAppApi.kt](https://github.com/MilLoong/UESTC-EAMS-Helper-App/blob/e8d73160f2b7e4e74df389053e0dcecbca144531/app/src/main/java/edu/uestc/eams/helper/data/eamsapp/EamsAppApi.kt)：使用 `eamsapp.uestc.edu.cn` 移动教务接口，按学期、学号和教学周读取。这是另一套 API，不能直接当作用户提供的桌面 EAMS URL 的协议。
- [ValidWeeksBinary.kt](https://github.com/MilLoong/UESTC-EAMS-Helper-App/blob/e8d73160f2b7e4e74df389053e0dcecbca144531/app/src/main/java/edu/uestc/eams/helper/data/parser/ValidWeeksBinary.kt)：将首个 `1` 归到第 1 周。这与学校公开静态源码的周起点模型存在冲突，迟开课课程可能被提前，不应照搬。

该项目许可证为 MIT。其源码证明另一条实现路径存在，不等于本次已验证它的移动教务 API、Android 认证或会话兼容性；本次实际验证的是用户在 Edge 打开的桌面 EAMS 课表。

## 学期选择与会话

建议沿用学校网页自己的学期选择和课表加载流程，在用户选定学期并完成加载后读取。无需生成学生 ID 或推测学期 ID。

若后续需要自动重新加载，必须先从当前登录页面核查：

1. `courseTableForm` 中的 `semester.id`、`ids`、课表类型和其他实际表单参数。
2. 如果表单没有固定 `ids` 输入，检查它是否由页面 `searchTable()` 动态填入；学生课表与班级课表可能使用不同的 `ids`。
3. 学期选择可能来自 `dataQuery.action` 的 `semesterCalendar` 数据；应沿页面已声明的请求与可选项读取，不能用年份或递增规律猜测。
4. Cookie 应由 WebView 或浏览器自行管理，导入内容只保留课表字段。CAS 验证码、短信验证、设备确认交给用户在学校官方页面完成。

Classic EAMS 的公开示例通常向 `courseTableForStd!courseTable.action` 提交 `semester.id`、`ids`、`setting.kind=std`、`ignoreHead`、`startWeek` 等，但具体 UESTC 参数仍需真实页面确认，不应在此次实现里未经核实直接重放请求。

## 可以支持的内容与限制

可支持：课程名、教师、地点、星期、开始及结束节次、连续周、单双周、离散周、多段安排、同一格多项课程、同课程不同教室或不同教师的安排。原始课程 ID 可帮助识别同一课程，显示名应完整保留。

需要用户或学校页面确认：第 1 教学周周一、全学期周数、准确上下课时刻、选定的学期以及覆盖/追加现有课表的方式。不同开源项目的作息硬编码值存在差异，不能把其中一份当成学校当前标准。

未验证或暂不应承诺：用户在 Android 内置 WebView 的完整实际账号认证和导入流程、无需人工认证、绕过浏览器验证、后台自动登录、批量下载历史学期、研究生教务、其他学校、调休补课、尚未发布的课程以及跨年位串的全部变体。

解析失败应给出清楚的原因，保留当前课表。应用解析本地 HTML/JSON 时只读取数据，不执行导入文件中的 JavaScript。导入前应显示课程数量、周次/节次范围、学期和注意事项，用户确认后再保存。

## Android 后续验证清单

- 用户在内置 WebView 完成学校认证，确认验证码、短信或设备验证等实际登录步骤可正常完成。
- 通过“课程管理 → 我的课表”进入目标学期；若使用同源 iframe，核实可正确提取它的课表。
- 核对 Android 页面是否继续使用 `unitCount = 12`、`marshalTable(2, 1, 20)`，并比较星期、节次和起始周，排除错列或提前上课。
- 用单双周、1/2/4 节跨节、多课同格、教室变更、无教室和非连续周安排核对预览。
- 检查用户选定的学期与应用预览一致，确认并导入；不把 Cookie、学号、个人课表或认证页面提交到源码包。
